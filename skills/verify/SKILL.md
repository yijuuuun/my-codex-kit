# verify

1. 무엇을 검증할지 정한다: 이번에 바뀐 기능 + 과제의 필수 요구사항.
2. 자동 테스트가 있으면 실행한다. 없으면 핵심 경로에 대한 최소 테스트를 만들거나 재현 가능한 수동 확인 절차(명령·입력·기대 결과)를 적는다.
3. 웹 서비스라면:
   - 서버가 `0.0.0.0`에 바인딩됐는지, 실제 포트가 몇 번인지 확인한다.
   - `curl -s http://127.0.0.1:<포트><경로>`로 응답을 확인한다.
   - 사용자에게 플랫폼 Browser 도구에 입력할 PORT와 경로를 알려준다.
4. 실행한 명령과 실제 출력 요약을 보여준다. 실패하면 원인을 분석하고 고친 뒤 다시 검증한다.
5. 결과를 `DECISIONS.md`의 "검증 결과 요약" 표에 통과 / 실패 / 미검증으로 기록한다.
6. 제출 전 점검이면 추가로 확인한다:
   - 필수 파일 존재와 경로
   - README에 실행 방법이 있는지
   - 모든 변경 커밋 여부 (`git status`)
   - 키·토큰이 파일에 남아 있지 않은지
