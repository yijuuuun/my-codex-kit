# plan-and-log

## 시작할 때
1. README와 작업 공간의 파일 목록을 확인하고 요구사항을 빠짐없이 뽑는다. 요구사항마다 출처(파일·섹션)를 적는다.
2. 필수 제출 파일명·경로·형식이 지정되어 있는지 따로 표시한다.
3. 애매한 점을 질문 목록으로 만든다.
4. `~/.codex/kit-templates/PLAN.md` 또는 `.kit/templates/PLAN.md` 형식(없으면 아래 항목)으로 작업 공간 루트에 `PLAN.md`를 만든다:
   목표 / 요구사항 표 / 확인할 점 / 접근 방법 / 단계별 시간 배분(총 180분, 마지막 15분은 문서·제출용) / 리스크.
5. 사용자에게 계획을 짧게 요약해서 보여주고 확인을 받는다.

## 작업 중
- 구조·라이브러리·알고리즘·트레이드오프 등 의미 있는 판단을 할 때마다 `DECISIONS.md`에 항목을 추가한다:
  결정 / 이유 / 대안과 버린 이유 / 검증.
- 요구사항 표의 상태를 갱신한다.

## 마무리할 때
- `DECISIONS.md`의 "검증 결과 요약"과 "남은 한계와 개선 방향"을 채운다.
- 사용자가 AI 없이 5분 안에 설명할 수 있도록 핵심 판단 3~5개를 한 줄씩 요약해서 보여준다.
